# 拾阶 · STAIR

个人投资管理应用，经典 uni-app / Vue 3 / TypeScript 工程。H5 在本机调试，App-vue 编译安卓资源，不另建 H5 网站再套壳。

## 本地运行

使用 Node 22（当前验证版本22.20.0）及 npm：

```sh
npm ci
npm run dev:h5
```

打开 http://127.0.0.1:5178 。默认首页为账户，不自动加入标的或示例资金。在自选点击添加，选择场内 ETF 搜索 `510300`，或选择场外基金搜索 `110022`，加入后查看真实报价与最近历史。

```sh
npm run typecheck
npm test
npm run build:h5
npm run build:app
```

H5产物在 `dist/build/h5`，App资源在 `dist/build/app`。**App资源编译不是生成APK，也不能证明安卓网络或设备能力已经验证。**

H5开发服务器仅绑定127.0.0.1，通过固定来源路径代理行情，免费源不需要密钥；不提供任意URL代理。代理仅本机开发使用，不进入App。H5生产包按浏览器跨域规则工作，东方财富接口未允许CORS，因此当前不承诺把H5静态包直接部署后仍可搜索和查询基金。安卓App通过 `uni.request` 直连，不依赖电脑代理。

## 当前范围

- 四Tab页面，自选搜索、持久保存/移除、启动刷新与手动刷新。
- 腾讯ETF市场价、未复权收盘序列；东方财富基金搜索与正式单位净值。
- 近一月/三月/半年/一年真实走势；ETF支持分时、日K及由日K聚合的周/月K。首次取180条，常规刷新重叠近10日后合并；扩大范围回补最多640条，实际覆盖以起止日期为准。分时按切换请求并单独缓存，不持续轮询。
- 招行黄金账户公开双侧价，已用用户银行端同一产品买卖价对照；高侧为客户买入，低侧为客户卖出。加仓用买入价，估值和止盈用卖出价；非交易状态不产生新提醒。图表统一使用上金所Au99.99免费分时与日线，支持分时/近一月/三月/半年/一年和每日涨跌。银行报价不再写入本机采样历史；市场曲线不进入招行账户策略判断。
- 本地账户、现金转入转出、已有持仓导入、实际买卖、场外申请/正式确认/撤销；历史重放计算持仓成本及卖出盈利，交易记录和标的详情提供扣费后的卖出盈利合计。已确认成交可从详情更正，保留原ID、记录顺序及原值；提交前确认整账重算，后续超卖等不合法结果拒绝整笔更正。初始为空，测试资金只存在隔离验收浏览器和模拟器，不包含在APK中。
- 独立计划参数、预算预留、单档加仓提醒及采样高点回撤；首页持仓和计划卡保留Demo布局。参数/提醒历史、公开分红折算公告发现及手工核对已接入；待核对事件阻止策略，确认后仍保持暂停，核对后手动恢复。报价刷新同时核对公告，失败保留缓存且不生成新提醒；公告只生成待核对记录，不推断实际到账。
- 实际成交B/S点、同位置循环点击共用明细、历史分段成本/买点/已生效采样止盈线，支持指针、缩放/平移、全屏。分时只标实际有时刻的成交；缺参数/高点不补造历史策略线。H5与Android15隔离模拟器已验证。
- 积存金支持克/元双向联动，按最后编辑的一侧和实际单价换算，修改单价沿用同一依据；保存录入依据供更正时沿用。新鲜可用报价仅预填对应客户买卖侧，异常行情留空待银行实际值。实际成交单价和手续费由用户确认，行情只用于估值和提醒。
- “我的 → 数据备份与恢复”支持账本JSON导出、版本/SHA-256校验、恢复预检与整体替换。恢复前副本与新账本同事务提交，保留最近一次供再次预检回退。H5文件下载/导入/重启回退及Android15真实SAF导出/读取/恢复前副本回退已验证。
- 当前APK仅ARM64；模拟器验证不代替个人真机及其他厂商系统兼容性确认。

自选与公开行情使用独立 `stair.watchlist.v1` / `stair.market.v1` 本地键，不读取HTML Demo的旧数据。交易账本在H5使用IndexedDB `stair-ledger`，App使用私有 `_doc/stair-ledger.db` SQLite，两端不共享数据库；浏览器调试数据不会自动搬到安卓。现金与持仓投影和原始流水同事务提交，失败不清库/不回退普通缓存，多页面旧版本保存会拒绝覆盖。Android15已核对真实SQLite实体/持仓投影、实际买卖扣费盈亏、恢复及副本回退；其他厂商仍待验证。

## 来源与测试

行情不使用账号Cookie或付费Token，不自动下单。免费接口无稳定契约，失败显示原因并保留上次缓存，不生成新提醒。ETF使用腾讯UTF-8历史接口中的qt即时字段，避免执行远端JS文本。场外基金不读取估值接口。

`tests/fixtures`保存2026-11-18公开只读接口样本，用于确定性解析回归，不是用户数据。测试不要求联网；真实来源可用性需要另行验证。

工程依赖版本参照DCloud官方 `uni-preset-vue` 的 `vite-ts` 分支固定，不使用混合版本的uni-app组件。

新建独立本地仓库，分支 `codex/work-004-stair-app`，尚无提交与远程。当前所有源码均未提交；后续按用户授权再commit并关联远程。

视觉与交互以已批准HTML Demo为基准：蓝色#2858df、灰蓝背景#f5f7fb，直接复用原图标路径与组件尺寸；真实账户为空仅改变数据及空状态，不更换设计风格。

账本口径：金额/费用以元记到分，价格/数量最多8位小数，使用decimal.js精度40运算；部分卖出的成本分摊保留余数，显示才四舍五入，最后清仓结转剩余成本。买入含费进成本，卖出到账扣费；导入不扣现金、不伪造过去买点。同账户同日有未填时间的成交须明确确认记录顺序；资金转入按日初、转出按日末处理。场外基金确认保留原申请日期，以实际确认日期与数量/净值入账。

策略只在打开/返回App或手动刷新成功时判断；请求时间须在15分钟内，市场日期超过7个自然日不生成新信号（长假后等待新报价）。采集高点不是全天最高价，失败/离线缓存和非交易状态黄金不产生新判断。预算按关联本轮的累计买入含费计，卖出不恢复预算。导入缺少上次实际买价时，不能以持仓均价推测下一加仓价。

## 账本备份与恢复

在“我的 → 数据备份与恢复”导出JSON文件，最大10MB。文件包含账户、标的身份、导入基准、资金流水、全部买卖/申赎及计划，采用`stair-book`格式、`schemaVersion:1`和规范化内容SHA-256校验（对象键排序，数组保持顺序，含导出时间与版本）。这是完整性校验，不是加密或身份签名。文件包含个人账目，自行保管；应用不上传内容。自选和行情缓存保留目标设备内容，账户持有标的的身份仍随账本迁移。

选择文件只做预检，展示账户/持仓/成交/计划数量和现金合计；核对后勾选整体替换并确认。未知版本、校验失败、超卖/失效引用等不合法账本拒绝导入。预检后账本有更新须重新预检；数据库版本冲突也拒绝覆盖。导入时原有账本与新数据同事务写入，原有副本保留最近一次；普通记账不覆盖这份副本，可从“预检恢复前账本”回退。恢复后的本机revision继续递增，不采用文件内revision覆盖并发版本。

历史交易、费用、成本、预算和手动暂停状态恢复原值；观察高点和待执行提醒清除，等待新行情重新判断，避免跨设备沿用旧信号。副本也存于本机数据库，卸载/清理应用后会消失，长期保留请另行导出文件。

IndexedDB数据库结构v1→v2增加`recovery`表，v2→v3增加`corporateActions`表，不清空旧实体，业务账本schema仍为1。SQLite新增同名表并使用原有事务。浏览器导出后应在下载列表确认保存；安卓使用系统文档选择器的创建/打开操作，UTF-8分块读写及10MB限制，无需增加全盘存储权限。Android15已通过真实系统文件选择、UTF-8读写、预检、SQLite恢复及副本回退；其他厂商文档选择器及个人真机仍待验证。

实现依据：[Android文档选择器](https://developer.android.com/training/data-storage/shared/documents-files)、[DCloud Native.js](https://www.html5plus.org/doc/zh_cn/android.html)。备份路径不连接持续服务端、不经免费行情代理。

## 计划历史

从计划卡片进入详情，在“本轮投资计划 → 参数与提醒历史”查看。创建/修改参数保存版本与调整前后快照；暂停、恢复、申赎申请/撤销、实际成交和恢复账本留下独立记录。有效行情只在开始观察、更新采样高点、产生/撤回提醒时记录，不因重复刷新刷屏。展开可查看当时预算、参数、单位成本、上次实际买价、下一买点/回撤止盈线及行情所属日期和来源。这里是实际采集记录，不是未打开App期间的历史行情回放，也不会补单。

历史随计划实体同事务保存，包含在JSON备份中；兼容旧计划缺少history的情况，不补造旧记录。恢复保留已有历史并追加“恢复账本”，清除旧提醒和高点。分红拆分在同一账本事务重放数量/现金/参考价调整并追加暂停历史。

## 分红与拆分

详情页→分红与拆分，手工登记公告及本账户实际权益。公开来源按代码核对分红及折算表，只对基准后实际持仓自动登记待核对事件；无权益、代码不匹配和结构错误明确区分。待核对只暂停，不改变账目。正式确认需核对来源、生效日前份额、实际到账/再投确认日期及开盘前计算顺序：现金分红按实际净到账增加现金及已实现收益，历史买入总成本不冲减；红利再投按确认金额增加成本和实际新增份额，不占追加预算；份额拆分保持总成本，改变数量、单位成本及参考买价。确认记录不能覆盖，重复提交幂等，修正历史前请备份并核对后续流水。

不把分红/再投冒充普通买卖，不把拆分当损益。生效日早于或等于已有持仓导入基准时拒绝重复入账。当前同账户同标的同日仅允许一项权益，复杂组合须先核对，不自动猜测。

除息生效日只调整参考买价，现金分红与再投份额在实际到账/确认日重放；公告发放日仅预填，未到账不确认。旧备份缺cashDate时保持原生效日到账口径。历史图表按截止日重放，不能提前展示尚未确认到账的份额。

## 本地复用原生包构建

官方安心打包初包保留在`dist/release/apk/__UNI__A7ED73C__20261119120748.apk`。同一工程的页面资源更新可本地重建，不必每次重新排队。先用HBuilderX CLI导出当前资源，再运行脚本：

```sh
/path/to/HBuilderX/cli publish app-android --type appResource --project /absolute/path/to/stair-app
python3 scripts/build-android.py --base-apk /path/to/official-base.apk --apktool /path/to/apktool_3.0.3.jar --pack-tools /path/to/HBuilderX/plugins/app-safe-pack --signing-config /private/path/signing.local.json --java /path/to/java17/bin/java --output dist/release/apk/stair-0.1.8-arm64.apk
```

脚本只支持当前原生初包：按工程配置更新权限/SDK版本/应用版本/图标及导出www资源，保留全部官方DEX与原生库，校验原生代码逐字节一致、所有导出资源一致、zipalign及原签名证书后才替换输出；旁边JSON记录SHA-256与签名校验结果。新增原生模块或升级DCloud运行时需重新取得官方原生包。仅修改源码后直接运行脚本不会自动导出最新资源，须先完成前一步导出。签名JSON只放仓库外，字段为storeFile、alias、storePassword、keyPassword，密码经环境变量交给签名工具，不写命令行。工具路径由本机提供，不下载或运行远端脚本。

官方Apktool3.0.3发布文件SHA-256在脚本中固定核验；构建失败保留原APK。初包、密钥和工具链均须独立保管，Git源码不包含这些本机文件。参考[Apktool官方发行](https://github.com/iBotPeaches/Apktool/releases/tag/v3.0.3)及[DCloud权限说明](https://uniapp.dcloud.net.cn/tutorial/app-permission-android.html)。

## 0.1.4 黄金走势

招行黄金账户新增当日分时（默认）与历史采样切换。仅详情可见且App前台时约每30秒获取一次同产品双侧报价；离页/后台停采，已发请求可完成缓存但不重新建立计时器。仅当日有效交易报价形成分钟点，同分钟保留较新来源秒，超过2分钟缺口断线。报价来自北京时间，过期缓存不伪装成今日分时，ETF/基金口径不变。

历史仍是本机每天最后一次有效报价，不是正式日收盘；近一/三月等仅筛选已有覆盖。采样变化按卖出价相对前次采样计算，保留基准日期和间隔天数，首条无基准显示—。无同产品验证历史接口时不回补，不使用上金所或其他银行替代。免费报价接口未承诺长期稳定，也不读取银行账户。升级0.1.4继续同签名覆盖，先导出外部账本JSON，不卸载清数据。
